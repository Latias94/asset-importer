# asset-importer 0.9.0

This release updates `asset-importer` and `asset-importer-sys` to Assimp 6.0.6 and tightens the contracts around scene ownership, native data decoding, callbacks, and export. It contains breaking changes from 0.8; review the migration guide before upgrading. The minimum supported Rust version remains 1.85.

## Highlights

- Assimp 6.0.6 fixes glTF normalized skin weights, mixed joint accessors, and texture transforms, with Rust regression coverage for these cases.
- Imports retain their native importer, allowing later post-processing and memory queries while keeping custom I/O alive for the scene's lifetime.
- Material and metadata decoding preserve unknown native values and report malformed data without unchecked native conversions.
- Callback errors retain their original I/O error kind and message; exports report the Exporter's own diagnostic and observe output write and flush failures.

## Upgrade from 0.8

```toml
[dependencies]
asset-importer = "0.9"
```

The default builds bundled Assimp from source. Select `prebuilt` or `system` explicitly when needed; build-mode features are mutually exclusive. The optional `glam` integration now uses 0.34. The `tokio` and `nozlib` features were removed; use your application's async runtime and the platform's required zlib support.

`Scene::apply_postprocess` requires exclusive ownership of an imported scene. Drop scene clones, views, and owning iterators first, or configure processing before import. Raw adopted scenes cannot use safe post-processing. `ExportBuilder::with_preprocessing` was removed; prepare the scene through its import builder or `Scene::apply_postprocess` before exporting.

Native enums exposed by `raw-sys` are integer newtypes; use `.0` instead of enum casts. `ShadingModel::PbrBrdf` replaces the workflow-specific PBR variants. `Error::IoError` now retains the original `std::io::Error`, and `Error::from_assimp()` was removed. The native global logging facade was also removed; log operation results and progress in your application.

Property stores retain the final value per native type space. Smoothing-angle constants are split into `NORMAL_MAX_SMOOTHING_ANGLE` and `TANGENT_MAX_SMOOTHING_ANGLE`; use `DEBONE_THRESHOLD` for deboning and `GLOBAL_SCALE_FACTOR` for user scaling. See the [complete migration guide](../../README.md#migrating-to-09) for remaining API changes and examples of the supported build modes.

## Native limitations

The safe API and bridge reject `SplitLargeMeshes` and `SplitByBoneCount` because Assimp 6.0.6 can invalidate scene ownership or fail to advance. Global scaling rejects zero or nonfinite effective scales, and nonidentity scaling rejects morph targets without positions. Such morph targets remain importable without scaling or with an effective scale of one.

Scene copies used for export and hierarchy-preserving pre-transformation reject sparse morph channels that Assimp cannot copy safely. Export also rejects unsupported node metadata and mesh-animation layouts. Blob and custom-I/O 3MF exports are unavailable because the native ZIP writer bypasses I/O handlers; explicit native-path 3MF export remains supported.

The raw upstream bindings remain unsafe and do not provide the bridge's protections. Prebuilt consumers require newly generated 0.9.0 archives containing Assimp 6.0.6. Until those artifacts are attached to the release, use the default source build or local archives through `ASSET_IMPORTER_PACKAGE_DIR`.
